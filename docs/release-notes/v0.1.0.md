## OpenPM 0.1.0

The first release: self-hosted project management for small teams, with Kanban boards that update
live, on Docker Compose or Kubernetes.

### What's in it

- **Workspaces and people:** sign up creates a workspace. Invite people by email with a role
  (viewer, member, admin, owner), change roles, remove members. Profile and password changes; a
  password change signs out every other device.
- **Projects and boards:** projects with Kanban boards (To Do, In Progress, In Review, Done). Drag
  cards with the mouse or the keyboard. Archive or delete projects.
- **Tasks:** title, description, status, priority, assignee and due date, all editable in one dialog.
  Labels, comments with @mentions, file attachments (any S3-compatible storage), search and filters.
- **Live and notified:** boards update live for everyone viewing them. In-app notifications for
  assignments and mentions; assignment emails through Resend.
- **Dashboard:** your open, overdue and due-soon tasks, and recent activity.
- **Accessible and responsive:** WCAG 2.1 AA checks on every screen in CI, full keyboard use, and a
  phone layout.

### Running it

- **Docker Compose:** `echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env && docker compose up -d --build`.
- **Kubernetes:** a Helm chart with autoscaling, disruption budgets, default-deny network policies,
  hardened pods, Prometheus metrics, Grafana dashboards and alert rules. Argo CD apps for dev
  (auto-sync) and prod (manual sync, digest-pinned images, a smoke test after each sync).
- Images: `ghcr.io/vxrdhxn/openpm-{api,worker,frontend}:0.1.0`, with SBOM and provenance.

### Before you upgrade from a pre-release checkout

There are no built-in credentials any more. The Helm chart refuses to render, and Compose to start,
until you set your own. The API refuses example secrets from this repository in production. If you
ran with the old defaults, rotate them: [deploying.md](https://github.com/vxrdhxn/OpenPM/blob/v0.1.0/docs/deploying.md#upgrading-an-install-made-with-the-old-defaults).
The [security review](https://github.com/vxrdhxn/OpenPM/blob/v0.1.0/docs/security-review.md)
explains why.

The chart now sets `TRUST_PROXY=1` so rate limits apply per client behind the Ingress. If there
are more proxies in front of the Ingress controller, set `api.trustProxy` to match.

### Known limitations

- No full Content-Security-Policy, MFA or account lockout yet.
- No undo after deleting; archive projects instead to keep them.
- The in-chart Postgres has no scheduled backup job: use a managed database in production, or
  schedule `scripts/backup-db.sh`.
- Not yet tested with a screen reader end to end.
