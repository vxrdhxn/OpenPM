## OpenPM 0.2.0

Private projects, organization management, email-verified sign-up, a redesigned interface, and a
frontend that can run on Vercel with the API elsewhere.

### What's new

- **Private projects** with their own members, hidden everywhere a project shows (boards, search,
  dashboard, notifications, live updates).
- **Organizations:** owners, ownership transfer, settings, deletion, declinable invites (up to 500
  per organization). A separate admin sign-in and admin area.
- **Sign-up and accounts:** optional verify-by-email sign-up; changing the password requires the
  current one.
- **Notifications:** due-date reminders, per-user preferences, a retention policy, and notices when
  you are added to or removed from a project.
- **Tasks:** optimistic concurrency (the dialog no longer overwrites a teammate's edit) and undo
  after deleting a task.
- **Interface:** a new design system, home page, dashboard and board, light and dark themes.
- **Deploying:** frontend on Vercel with no custom domain. The frontend proxies `/api`
  (`API_PROXY_TARGET`), and live updates connect to the API with a single-use 30-second ticket
  (`POST /api/realtime/ticket`). Or `COOKIE_DOMAIN` for subdomains of one domain.
- **Security and operations:** audit log, nonce-based CSP, a least-privilege database user,
  WebSocket connection limits and backpressure, scheduled verified Postgres backups in the chart,
  a values schema, pods spread across nodes and zones, an OpenAPI 3 spec (`docs/openapi.json`).

### Upgrading from 0.1.0

- Migrations 020 to 030 run on upgrade (`migrate up`); all have down migrations.
- The API and worker now connect as their own database user, `openpm_app`, which the migrations
  create: set `DATABASE_APP_PASSWORD` (Compose) or the chart's equivalent before upgrading
  ([database-access.md](https://github.com/vxrdhxn/OpenPM/blob/v0.2.0/docs/database-access.md)).
- The browser's live-updates socket now authenticates with a ticket. Deploy the API and frontend
  together; an old frontend still works against the new API (cookie auth is kept).
